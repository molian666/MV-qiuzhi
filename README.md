# mianshi · 求职操作系统

本地优先的求职操作系统：**面试模拟与复盘 → 评分与纠错 → 薄弱点训练 → 投递分析与半自动投递 → Offer 决策**。
完整方案、数据模型与路线图见 [`docs/PLAN.md`](docs/PLAN.md)。

## 环境要求

- Python 3.11+（本机 Python 3.14.6 实测通过）
- Node 20+ 与 pnpm
- **无需任何 API Key**：默认 `LLM_PROVIDER=mock`，全流程可离线跑通

## 快速开始

### 1. 后端

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env          # 需要真实模型时再改里面的配置
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

- 接口文档：<http://127.0.0.1:8000/docs>
- 健康检查：<http://127.0.0.1:8000/api/health>

### 2. 前端

```powershell
cd frontend
pnpm install
pnpm dev                              # http://127.0.0.1:5173
```

前端不直连端口：`/api` 由 Vite 代理到 `127.0.0.1:8000`（见 `frontend/vite.config.ts`）。

### 3. 一键启动（可选）

```powershell
.\scripts\dev.ps1              # 后端 + 前端
.\scripts\dev.ps1 backend      # 只起后端
```

> Windows 上若 `pnpm` 被 PowerShell 执行策略拦住（`无法加载文件 pnpm.ps1`），
> 用 `cmd /c pnpm ...`，或把执行策略放开：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`。

## 语音面试怎么用

前端 →「语音面试」标签：

1. 选岗位/简历（可留空）→ 题量 →「开始语音面试」（创建 realtime 会话并连上 WebSocket）；
2. 点「开始说话」授权麦克风，正常说话；面试官的问题会用浏览器朗读出来；
3. 你开口时面试官的声音会自动停掉（打断），也可以点「打断面试官」按钮；
4. 说完自动进入下一题；点「结束并保存」结束，录音可在「历史面试」里整场或逐回合回放。

**两种语音模式**（`backend/.env`）：

| 配置 | 行为 |
|------|------|
| `SPEECH_PROVIDER=mock`（默认） | 不需要任何 Key。音频照常采集、录制、存档、回放；"音频→文字"这一步由你输入的文本替代——页面会明确显示「转写：文字替身」，**不会假装已经识别了语音** |
| `SPEECH_PROVIDER=qwen` + `DASHSCOPE_API_KEY=...` | 阿里云百炼实时语音识别（`qwen3-asr-flash-realtime`），说话即转写 |

面试官的"说话"目前用浏览器 `speechSynthesis` 播报（`audio_mode=client`）：零依赖、中文音色开箱可用，
让 M1 在没有服务端 TTS 的情况下也能真的听见对话。服务端 TTS 的协议位已留好
（`app/providers/tts/base.py`），接入后把 `audio_mode` 切到 `server`，音频改由 `audio_chunk` 事件下发，
前端播放器不用改。

> ⚠️ 如果你的机器开着系统代理（VPN / Clash 等），httpx 与 websockets 会尝试走代理而连不上国内接口。
> 本项目默认 `TRUST_ENV_PROXY=false` 显式绕过系统代理；确实必须经代理访问时才设为 true。

## 报告怎么用

面试结束后，顶部「报告」标签 → 选一场面试：

1. 没有报告时**自动生成**（`POST /report`）；已有报告直接复用，不会重复烧 token；
2. 报告包含：总分（0–100）、七维雷达图、整体评价、逐条改进项；
3. 每条改进项都带：**原话证据**（可点「回放这段」直接听音频）、怎么改、用你自己经历重写的示范答案、
   立刻可做的练习、能力标签（M5 会用这些标签做针对性训练）。

评分维度写死在 `app/analysis/rubric.py`（保证同一场面试多次评分**可比**，否则趋势图没意义）：

> 切题度 / 结构 / 信息密度与量化 / 技术深度与正确性 / 表达与流畅 / 时间控制 / 主动性

模型分工：评分与纠错走 `deepseek-reasoner`（质量优先），实时对话走 `deepseek-chat`（延迟优先）——
按调用任务（`task`）自动选择，见 `app/providers/llm/deepseek.py`。

接口：`POST /api/sessions/{id}/report?force=true|false`、`GET /api/sessions/{id}/report`、`GET /api/reports`。

## 训练怎么用

生成面试报告之后，去「训练」标签：

1. 顶部是总览：平均掌握度、高危薄弱点、待复习数量、能力标签数；
2. 「今日训练」默认给 **3 道薄弱点题 + 1 道随机题**；每题都能展开「为什么推荐这题」看到打分依据；
3. 点「开始作答」写答案 → 提交后立刻批改（分数 / 一句话点评 / 示范 / **掌握度变化**）；
4. 右侧「能力掌握度」按薄弱程度排序，点任意一项看它的**掌握度曲线**——
   每次变化都能追溯到来源（报告 or 训练）与当时得分。

**掌握度怎么算**（能手算复现，不做黑箱）：

```
new = old + 0.3 × (目标 − old)      目标 = (得分 − 1) / 4 × 100
首次观察直接取目标值（否则会被 0 起点稀释，用户觉得"练了没反应"）
```

- 低于 40，或最近连续两次都落在低分区 → 标记为**高危薄弱点**；
- 复习节奏用标准 SM-2：答对依次 1 天 → 6 天 → n×ease；答错回到 1 天重来。

**题目从哪来**：优先用题库里已覆盖薄弱标签的题；没有就调用模型现场生成并**写进题库**
（下次直接复用）——所以 M5 不依赖题库功能也能自成闭环。入库与组题都会按题干去重。

## 节奏学习怎么用

打开「节奏学习」标签：

1. **添加对话**：粘贴一段真实面试的对话文稿（`[面试官] …` / `[我] …`，也支持 `00:12 面试官：…` 和 `Q: / A:`）。
   带时间戳时「等待时长」是**实测**的，不带时按字数估算——页面上会标明来源，不假装测准了。
2. **生成画像**：勾选 1..N 段录音 → 学出面试官画像。多段会**合并统计**（同一个面试官的不同场次越学越准）。
3. **画像长这样**：风格标签（如「紧盯细节连续追问」「给足思考时间」）、题型配比、追问深度上限、
   压力水平、面试官语速、开场/收尾方式，外加每题一条的节奏样本（题型/追问数/等待时长）。
4. **在模拟中生效**：去「面试间」或「语音面试」，配置区选「面试官画像」：
   - 面试官的行为指令会带上画像（题型配比、追问深度、压力水平）→ 同一套题库也能问出不同风格的面试；
   - 语音模式下的**等待时长**跟着画像走（面试官问完等得久，系统也给更多沉默时间再判定"说完了"）；
   - 会话详情里能直接看到这场用的策略。

> 转写：默认 `ASR_PROVIDER=mock`，文本来自你粘贴的文稿——**不会识别音频内容**（音频仅保存）。
> 真识别音频需要接百炼文件转写（含说话人分离）：接口已留（`app/providers/asr/qwen_file.py`），
> 但上传与异步任务那条链路我没用真实 Key 验证过，所以没有先写一版"看起来能用"的代码。

## 简历与话术怎么用

两个页面：**简历体检**（这份简历投这个岗位差在哪）和 **故事与话术**（面试时说什么）。

### 简历体检

1. 在「简历与版本」里建一份简历（纯文本）。想投不同侧重点的岗位就**另存为新版本**——
   之后在投递分析里能比较哪个版本的回复率高。
2. 把目标岗位的 JD 整段粘到「JD 正文」，点**开始诊断**。

诊断会给三样东西：

- **匹配度与等级**：JD 里「必须精通 X」算硬性要求（权重 1.0）、「熟悉 X」算职责相关（0.7）、
  「X 优先」算加分项（0.5）——不是简单地数关键词个数；
- **三分类**：已覆盖 / 缺失（按权重排序，标了硬性还是加分）/ 简历里有但 JD 没提（这是这一版可以精简的部分）；
- **逐条改写建议**：每条缺失关键词都会指出**该补在哪段经历里**，并给一个句式模板。

> 关于「不编造」：改写建议只给句式（「负责 …，使用 X 完成 …，把 … 从 A 改善到 B」），
> **省略号和 A/B 必须你自己填**。工具不会生成「我用 Kafka 把吞吐提升 300%」这种
> 听起来漂亮但可能不存在的经历——求职材料里编造事实的代价远高于少一条建议。

另外还有 **ATS 格式体检**（不需要 JD）：全角字符（`Ｐｙｔｈｏｎ` 会让关键词匹配直接失效）、
缺联系方式、没有可解析的时间线、超长不分段、成果里没有量化数字、项目符号混用等。

**年限是怎么算的**：从简历里的日期区间推算，并**合并重叠区间**——
「2021.03-2023.06 在 A 公司」和「2022.01-2022.12 兼职」是重叠的，直接相加会虚报。

页面底部还有「匹配度 vs 回音」：用投递记录里的 JD 反推每条投递的匹配分，按分数段统计回复率。
这是"为什么没回复"最直接的证据（样本不足时会明说样本不足）。

### 故事与话术

- **STAR 故事卡**：从简历里抽取出你的真实经历，整理成 背景/目标/做法/结果 四段。
  这里抽出的卡片**会被模拟面试真正引用**——面试官问「讲一个你线上出故障的例子」时，
  它拿到的是你那张「支付链路高可用改造」的卡，追问会落在你真做过的事上，而不是模型编的项目。
  页面会提示你哪类故事还没有（比如一张「失败复盘」都没有，被问到就答不上来）。
- **自我介绍**：30/60/180 秒三个版本，按中文口语约 3.3 字/秒控制字数，配**计时练习**
  （同一个内容要能说完，才叫准备好了）。
- **敏感题**：离职原因、空窗期、职业规划、期望薪资、最大不足、频繁跳槽。
  会给**策略**（怎么说，比如"离职原因不要抱怨前雇主、把重点放在我想去哪里"），
  答案里带方括号的空白**要你自己补**——策略可以给，事实必须你有。
- **反问清单**：结合 JD 生成能听出信息的反问（而不是"公司文化怎么样"这种只能得到套话的问题）。

## 半自动投递怎么用

打开「投递执行台」。**这个功能默认关闭**，且必须勾选风险确认才能开启——理由写在下面。

**它是什么**：抓岗位 → 过滤掉你不想投的 → 打分排序 → 你逐条确认 → 按限速发出去。
**它不是什么**：不是无人值守的批量投递机器人。

### 四步

1. **开启模块**：选平台（`Mock 演练` 或 `Boss 直聘`），勾选风险确认。
   平台选 Mock 时不会碰任何真实网站，适合先把流程跑一遍。
2. **抓取候选**：填关键词（空格分隔）→ 点「抓取候选」。
   这一步**只入队，不投递**。被过滤拦下的岗位会连原因一起列出来，例如
   「拦住：猎头岗位；HR 长期不活跃；薪资 12-18K 与期望 20000-80000 无交集」。
   不通过的岗位也会落库，方便你回头核对规则是不是太严。
3. **逐条确认**：勾选要投的 → 可以**直接改招呼语**（AI 生成的初稿往往需要你加一句自己的话）→
   点「确认投递」。不想投的点「跳过」。
4. **投递**：点「开始投递」。第一次建议**勾着「演练模式」**跑一遍（只报告会投什么，不真的发送）。

### 三道安全边界

| 边界 | 具体行为 |
| --- | --- |
| **人工确认闸门** | 投递只发生在"已确认"的记录上。后端的 `/execute` 也只处理这些——接口层面就没有"直接投"的入口 |
| **限速** | 默认每分钟 ≤3 条、每天 ≤30 条，每条之间随机等 3–9 秒（固定间隔本身就是机器特征）。这两个上限有硬天花板（10/60），设置页改不上去 |
| **熔断** | 一旦检测到验证码、滑块或登录失效，**立刻停止并停投当天剩余时间**。页面改版这类"我们自己的适配问题"只停本轮、不停当天——不该拿你的账号替我们的 bug 买单 |

### 过滤规则

首次打开会自动建一套规则（黑名单 / 已投过去重 / 排除猎头 / HR 需活跃 / 薪资区间 / 屏蔽外包驻场），
在页面底部可以直接开关。规则存在 `apply_rule` 表里，任何一条命中就拦下这个岗位，理由是具体的、可见的。

### 关于 Boss 直聘

Boss 适配器已经写好（patchright + 真实 Chrome + 持久登录 + 人类化节奏 + 逐字输入），
但**选择器需要在你的真实页面上校准一次**。没校准前，状态栏会明确告诉你还缺哪些字段并拒绝投递。

校准步骤见 [`docs/APPLY_SELECTORS.md`](docs/APPLY_SELECTORS.md)（含取选择器的方法、验证顺序、常见问题表）。

> 本项目**不实现**验证码绕过、多账号轮换、代理 IP 池、指纹伪造。
> 出现验证码就停下来——这是设计意图，不是缺陷。平台规则是否允许自动化操作，请你自行评估。

## 投递分析怎么用

打开「投递分析」标签。数据有两条来源：

**① CSV/TSV 导入（任何平台都能用）**

把投递记录复制到 Excel 另存为 CSV，或直接粘贴表格，贴进右侧导入框：

- 表头支持中英文常见写法（公司/Company、岗位/Position、渠道/Platform、状态/Status、投递时间/Apply Date、简历版本/Resume）；
- 状态与渠道会自动归一化（"Boss直聘/BOSS 直聘/boss" 都算 boss；"已读/已查看" 都算 viewed）；
- 日期支持 `2026-03-12`、`2026/3/12 14:30`、`2026年3月12日`、`20260312`、Excel 日期序列号；
- **按「同公司 + 同岗位 + 同一天」去重**，重复导入不会重复记；导入报告会列出**没认出来的列**（那些列不会被静默丢掉）。

**② 浏览器扩展（需要本机后端在跑）**

见 [`extension/README.md`](extension/README.md)：Chrome/Edge 开发者模式加载 `extension/` 目录 →
在平台的**投递记录页**点扩展图标 → 一键同步。它只读你自己已登录页面的表格，不模拟登录、不绕过验证码。

> 扩展**没有写死平台选择器**（平台 DOM 改得勤，写死的结果是"某天突然抓不到还没提示"），
> 而是用通用表格识别；抓不到时弹窗会告诉你去哪一页，并提示用 CSV 导入兜底。

**看板能给什么**：总投递 / 回复率 / 面试转化 / Offer；漏斗（含"面到终面才被拒"也算进面试）；
渠道对比（哪个平台回复率高）；最近 8 周趋势；**简历版本 A/B**（哪个版本回复率高）；
响应时长中位数；**待跟进**（投出超 7 天没动静的）；完整清单可随时改状态。

## 设计约定（写代码前先读）

1. **每次 LLM 调用必须带 `task` 标签**，并落 `llm_call` 表（成本与效果对比靠它）。
2. **`analysis/` 下的 AI 功能写成纯函数 + JSON schema 输出**，便于复用与测试。
3. **时间统一 `app.clock.utcnow()`**（aware UTC）——SQLModel 0.0.46 的 `UTCDateTime` 拒绝 naive 值。
4. **编排层不碰数据库**：`realtime/interviewer.py` 只决定"问什么"，落库与传输在 api 层。
5. 新功能先看 `docs/PLAN.md` §9.1 的预留约束，避免后续返工。
