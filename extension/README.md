# mianshi 投递同步扩展（MV3）

在**你自己已登录**的招聘网站页面上读取投递记录，一键同步到本地求职助手。

## 它做什么 / 不做什么

- ✅ 只读当前页面的表格内容，POST 到 `http://127.0.0.1:8000/api/applications/ingest`（本地）；
- ✅ 自动识别渠道（zhipin → boss / liepin → liepin / zhaopin → zhilian / 51job → 51job）；
- ❌ 不模拟登录、不抓取他人数据、不绕过验证码；
- ❌ 不向任何第三方服务器发送数据（除了你的本机后端）。

## 安装（开发者模式）

1. Chrome/Edge 打开 `chrome://extensions/`；
2. 打开右上角「开发者模式」；
3. 点「加载已解压的扩展程序」，选择本目录（`extension/`）；
4. 确保本地后端已启动：在项目根目录执行 `.\scripts\dev.ps1`。

## 使用

1. 在平台里打开你的**投递/沟通记录**页面（不是首页、不是职位详情页）；
2. 点扩展图标 → 「同步这一页的投递记录」；
3. 弹窗会显示「新增 N 条 / 更新 M 条 / 跳过 K 条」，以及**没认出来的列**（那些列的数据不会被导入）；
4. 去「投递分析」页看漏斗与转化率。

## 抓取策略与已知限制

**不写死平台选择器**。招聘平台的 DOM 改得非常勤，写死选择器的结果是"某天突然抓不到、而且没有任何提示"。
所以扩展用「通用表格识别」：先看表头像不像投递记录（至少要认出两个列名，如"公司/职位/状态/投递时间"），
再按表头逐行取值。找不到 `<table>` 时会退一步尝试 `role="row"` 的网格布局。

限制（都是实话）：

- 页面结构差异大的平台可能抓不到 → 弹窗会提示"打开投递记录页再试"，实在不行用 CSV 导入兜底；
- 只同步**当前页**，分页数据要逐页点同步（避免翻页脚本引发风控）；
- 表头认不出来时不会瞎猜：会在弹窗里列出未识别的列名。

## 兜底：CSV 导入

任何平台都能用「投递分析 → 导入」：把页面表格复制到 Excel 另存为 CSV，
或直接从平台导出，粘进导入框即可。表头支持中英文常见写法（公司/Company、岗位/Position、
渠道/Platform、状态/Status、投递时间/Apply Date），日期支持 `2026-03-12`、`2026/3/12 14:30`、
`2026年3月12日`、Excel 日期序列号等。
